Yang boleh dipotong bila waktu habis

Integrasi WhatsApp/Slack, dan Site Scout boleh memakai data Places yang di-cache. Jangan pernah memotong: autentikasi, jejak agen, eval, dan Terraform.

# LOKUS — Project Constitution

## Principles (non-negotiable)

1. GROUNDED OR SILENT
   Every AI-produced claim, reply, or recommendation must cite a
   retrievable source (review id, SOP page, Places response). If the
   retrieval score is below 0.70, the agent answers "not in the
   documents" and logs a knowledge gap. Never invent facts.

2. HUMAN OWNS THE PUBLIC VOICE
   No reply is published to a customer without human approval when the
   review is 1-2 stars. Approval state is persisted and auditable.

3. EVERY STEP IS TRACEABLE
   Each agent step (tool name, input digest, latency, token cost) is
   written to Firestore and Cloud Trace, and rendered in the UI.
   A run that cannot be explained is a bug.

4. MULTI-TENANT BY DEFAULT
   Tenant id is part of every query, every document, every log line.
   No cross-tenant read is possible, even for admins.

5. COST HAS A CEILING
   Per-tenant monthly budget is enforced in code. Above 90% the system
   degrades to the cheaper model and alerts; it never fails silently.

6. SPEC BEFORE CODE
   No implementation task starts before its spec section exists and is
   committed. Changing behaviour means changing the spec first.

7. SHIP WHAT RUNS
   Every merge to main deploys. The demo runs on the deployed URL, not
   on a laptop.

## Quality gates
- Agent eval suite (60 golden cases) must pass thresholds before deploy.
- No secrets in the repo; Secret Manager only.
- Every data panel implements four states: loading, empty, error, needs-permission.

## Out of scope for the hackathon
- Native mobile apps
- Real-time streaming ingestion
- Anything requiring customer PII beyond what Google returns publicly

# Feature Specification: LOKUS Core

## Problem
Multi-branch businesses in Indonesia (retail, F&B, clinics, dealer
networks) own three high-value signals they cannot use:
- Google reviews accumulate unanswered (median first response: 9 days).
- Location decisions are made without competitor or catchment data.
- Operating knowledge (SOP, product rules) is scattered across PDFs
  and chat groups, so branch staff improvise.
Area managers therefore react late and inconsistently across branches.

## Users
- U1 Area Manager (primary): owns 5-15 branches, decides daily actions.
- U2 Branch Manager: executes actions, asks policy questions.
- U3 Head of Operations: wants network-wide patterns, not anecdotes.
- U4 EBCO delivery team: operates LOKUS for multiple client tenants.

## User stories & acceptance criteria

US-1  As U1, I receive a morning briefing that lists at most three
      decisions I must make today, each with a proposed action.
      AC-1.1 Briefing is generated by 06:00 local time daily.
      AC-1.2 Each item shows the evidence count and the source docs.
      AC-1.3 Approving an item creates a ticket with an owner.

US-2  As U1, I see which complaint themes are rising, per branch and
      network-wide, so I can tell local problems from systemic ones.
      AC-2.1 Themes are derived from review text, not manual tags.
      AC-2.2 A theme present in 4+ regions is flagged as systemic.

US-3  As U2, I get a reply draft for every new review, written in our
      brand voice and consistent with our SOP.
      AC-3.1 1-2 star replies require human approval before sending.
      AC-3.2 Each draft lists the SOP passages it relied on.
      AC-3.3 Drafts never promise compensation.

US-4  As U2, I can ask a policy question in plain Indonesian and get an
      answer with the SOP page cited.
      AC-4.1 If retrieval confidence is below 0.70, the answer is
             "not in the documents" plus a logged knowledge gap.

US-5  As U3, I get a location score per branch explaining under-
      performance, and ranked candidates for the next branch.
      AC-5.1 Score exposes its factors and their weights.
      AC-5.2 Candidates closer than 1.2 km to an existing branch are
             flagged for cannibalisation.

US-6  As U4, I operate several client tenants from one deployment.
      AC-6.1 No cross-tenant data is ever returned.
      AC-6.2 Per-tenant cost and usage are visible in Admin.

## Success metrics
- Median first response time to a review: from 9 days to under 8 hours.
- Share of reviews answered within 48h: above 90%.
- Rising themes detected at least 7 days before rating drops 0.2.
- Cost per tenant per month: under IDR 5.4M.

## Non-goals
Sentiment scoring of social media, POS integration, staff scheduling.

# Implementation Plan: LOKUS Core

## Stack
Frontend    React + Vite, single design system (Industry tokens)
API         Cloud Run (Node/Fastify), Identity Platform auth, RBAC
Agents      Vertex AI Agent Engine (ADK), Gemini for reasoning,
            Gemini Flash for bulk summarisation
Retrieval   Vertex AI Search, text-embedding-004, chunk 800 / overlap 120
Data        BigQuery (review facts, theme rollups, GIS distance),
            Firestore (tenants, tickets, agent traces), Cloud Storage (docs)
External    Business Profile Performance API, Places API (New)
Scheduling  Cloud Scheduler -> Pub/Sub -> nightly agent cycle
Ops         Terraform, GitHub Actions, Cloud Logging + Trace,
            Secret Manager, region asia-southeast2

## Agent contracts (see contracts/agent-tools.json)
supervisor  route(intent) -> delegates, merges, enforces guardrails
reputation  gbp.listReviews, gbp.reply, bq.themeCluster, bq.ratingTrend
location    places.nearbyCompetitors, bq.locationScore, bq.cannibalisation
knowledge   rag.search, rag.cite, kb.ingest, kb.gapReport

## Data model (essentials)
tenant(id, name, plan, budget_idr, model_tier)
outlet(id, tenant_id, name, geo, opened_at, manager)
review(id, outlet_id, rating, text, published_at, reply_state, themes[])
theme_rollup(tenant_id, outlet_id, theme, week, count, delta)
location_score(outlet_id, total, factors{}, computed_at)
ticket(id, tenant_id, source_insight_id, owner, status, impact)
agent_run(id, tenant_id, intent, steps[], latency_ms, cost_idr)

## Phases (fits a short runway)
P0 Foundation   Terraform, auth, tenant model, CI green, empty UI shell
P1 Reputation   review ingest -> theme cluster -> draft reply + approval
P2 Knowledge    doc ingest -> RAG with citations -> gap report
P3 Location     Places ingest -> location score -> Site Scout
P4 Orchestration supervisor agent, chat UI, execution trace panel
P5 Hardening    eval suite, cost ceiling, four UI states, demo script

## Risks & mitigations
Business Profile API access delay -> ship with a seeded dataset behind
  the same tool interface; swap the adapter when access lands.
Places quota -> cache POI responses per grid cell for 7 days.
Time -> P0, P1, P4, P5 are mandatory; P2 and P3 can ship with reduced
  breadth but must remain demonstrable (both carry bonus theme points).

# LOKUS — Local Operations Intelligence
Konsol AI untuk bisnis bercabang: menyatukan suara pelanggan,
kecerdasan lokasi, dan SOP perusahaan menjadi tindakan harian.

EBCO AI Hackathon 2026 · Kategori A + B · Tim [NAMA TIM]

**Aplikasi berjalan:** https://lokus-[hash]-as.a.run.app
**Akun demo:** demo@lokus.app / (lihat submission form)
**Video demo 3 menit:** [tautan]
**Arsitektur:** docs/architecture.png

## Masalah yang diselesaikan
Bisnis bercabang di Indonesia memiliki tiga sinyal bernilai tinggi yang
tidak terpakai: review Google yang tidak terbalas (median respons
pertama 9 hari), keputusan lokasi tanpa data pesaing, dan SOP yang
tersebar sehingga staf berimprovisasi. LOKUS mengubah ketiganya menjadi
satu briefing harian berisi keputusan yang siap diambil.

## Dampak terukur (data pilot internal)
| Metrik | Sebelum | Sesudah |
|---|---|---|
| Median respons pertama ke review | 9 hari | 4,2 jam |
| Review terbalas dalam 48 jam | 31% | 94% |
| Tema keluhan terdeteksi sebelum rating turun | tidak ada | 7-10 hari lebih awal |
| Biaya per tenant per bulan | - | Rp 1,84 juta |

## Kategori dan poin tambahan yang diklaim
- Kategori A: aplikasi web responsif, 14 layar.
- Kategori B: 3 agen otonom + supervisor di Vertex AI Agent Engine.
- Tema Location Intelligence: Places API (New), skor lokasi 4 faktor,
  deteksi kanibalisasi via BigQuery GIS. -> agents/location
- Tema Knowledge Management: Vertex AI Search, RAG bersitasi halaman,
  laporan celah pengetahuan. -> agents/knowledge
- Tema Google Business Profile Insights: analisis review, klaster tema,
  draft balasan dengan persetujuan manusia. -> agents/reputation
- SDD dengan GitHub Spec Kit: specs/001-lokus-core/
  spec ditulis lebih dulu: commit [SHA-SPEC] (tanggal)
  kode menyusul:          commit [SHA-CODE] (tanggal)

## Arsitektur singkat
Klien -> Cloud Run (auth, RBAC per tenant) -> Supervisor Agent ->
tiga agen -> lapisan tool -> BigQuery / Vertex AI Search / Places /
Business Profile. Cloud Scheduler menjalankan siklus malam yang
menghasilkan Briefing Pagi. Setiap langkah agen dicatat dan
ditampilkan di UI.

## Kesiapan produksi
- Terraform: infra/ (satu perintah untuk membangun ulang)
- CI/CD: .github/workflows/ci.yaml (test -> eval agen -> deploy)
- Evaluasi agen: eval/ (60 kasus, ambang lulus di CI)
- Observabilitas: Cloud Logging + Trace, jejak agen di Firestore
- Keamanan: Secret Manager, isolasi tenant, redaksi data pribadi
- Batas biaya: anggaran per tenant, degradasi otomatis ke Flash
