# Feature Specification: LOKUS Core

**Feature branch**: `001-lokus-core`
**Status**: ready for planning
**Language**: product UI in Bahasa Indonesia; code and docs in English

## Problem

Multi-branch businesses in Indonesia (retail, F&B, clinics, dealer networks)
own three high-value signals they cannot use:

- Google reviews accumulate unanswered — median first response 9 days, most
  never answered at all.
- Location decisions (open, relocate, close) are made without competitor
  density or catchment data.
- Operating knowledge (SOP, product rules, contracts) is scattered across PDFs
  and chat groups, so branch staff improvise and service becomes inconsistent.

Area managers therefore react late and inconsistently across branches, and the
network loses customers without knowing why.

## Users

- **U1 Area Manager** (primary) — owns 5–15 branches, decides daily actions.
- **U2 Branch Manager** — executes actions, asks policy questions.
- **U3 Head of Operations** — wants network-wide patterns, not anecdotes.
- **U4 EBCO delivery team** — operates LOKUS for several client tenants.

## User stories & acceptance criteria

### US-1 Morning briefing
As U1, I receive a morning briefing listing at most three decisions I must make
today, each with a proposed action.

- **AC-1.1** Briefing is generated by 06:00 local time, every day.
- **AC-1.2** Each item shows evidence count and the source documents it used.
- **AC-1.3** Approving an item creates a ticket with an owner and a due date.
- **AC-1.4** The briefing screen also shows what the agents did overnight as a
  timeline (reviews read, replies sent, documents indexed, tool failures
  retried).

### US-2 Theme detection
As U1, I see which complaint themes are rising, per branch and network-wide, so
I can tell local problems from systemic ones.

- **AC-2.1** Themes are derived from review text, not manual tags.
- **AC-2.2** A theme present in 4+ regions is flagged as systemic.
- **AC-2.3** Theme intensity is shown as a theme × branch matrix with an
  8-week trend per row.

### US-3 Reply drafts
As U2, I get a reply draft for every new review, in our brand voice and
consistent with our SOP.

- **AC-3.1** 1–2 star replies require human approval before sending.
- **AC-3.2** Each draft lists the SOP passages it relied on, with page numbers.
- **AC-3.3** Drafts never promise compensation.
- **AC-3.4** Guardrail results (4 checks) are visible before the send action.

### US-4 Policy answers
As U2, I can ask a policy question in plain Indonesian and get an answer with
the SOP page cited.

- **AC-4.1** If retrieval confidence is below 0.70, the answer is "tidak ada di
  dokumen" plus a logged knowledge gap.
- **AC-4.2** Each cited passage is clickable to the source page.
- **AC-4.3** The number of chunks considered but rejected is shown.

### US-5 Location intelligence
As U3, I get a location score per branch explaining under-performance, and
ranked candidates for the next branch.

- **AC-5.1** Score exposes its four factors (foot traffic, surrounding category
  mix, competitor density, parking/access) and their weights.
- **AC-5.2** Candidates closer than 1.2 km to an existing branch are flagged
  for cannibalisation.
- **AC-5.3** Two candidates can be compared factor by factor, with the agent's
  conclusion for each.

### US-6 Multi-tenant operation
As U4, I operate several client tenants from one deployment.

- **AC-6.1** No cross-tenant data is ever returned.
- **AC-6.2** Per-tenant cost and usage are visible in Admin.
- **AC-6.3** Role (admin / manager / viewer) is shown at tenant selection and
  enforced server-side.

### US-7 Conversational diagnosis
As U1, I can ask "kenapa rating cabang X turun bulan ini?" and get an answer
that combines reviews, SOP, and location context.

- **AC-7.1** The supervisor routes the question to the relevant agents and
  merges their findings into one answer.
- **AC-7.2** The execution trace (step number, tool name, result size, latency)
  is shown with the answer.
- **AC-7.3** The answer offers at least one action (create ticket, open
  reviews, show on map).
- **AC-7.4** Per-answer model cost is displayed.

## Success metrics

| Metric | Baseline | Target |
|---|---|---|
| Median first response time to a review | 9 days | under 8 hours |
| Reviews answered within 48h | 31% | above 90% |
| Rising theme detected before rating drops 0.2 | never | 7–10 days earlier |
| Ticket close time | not measured | under 5 days (SLA) |
| Cost per tenant per month | — | under IDR 5.4M |

## Non-goals

Social-media sentiment, POS integration, staff scheduling, native mobile apps,
real-time streaming ingestion.
